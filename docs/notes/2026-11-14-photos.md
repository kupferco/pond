# Photos page

`/photos` shows photos of earlier builds. Source of truth: one Drive folder: **Pond 1.0** in `Pond 2.0` (shared drive) → `Images and Videos` → `Online Gallery`. The sibling `Archive` folder is never synced. A sync copies
them into Cloud Storage (bucket of project `pond-grow`, folder `photos/`), not into git:
`photos/web/<driveId>.jpg` (max 1600 px), `photos/thumb/<driveId>.jpg` (max 400 px), `photos/index.json`.

- Idempotent: a file is skipped when its Drive id and modified time are unchanged. Images only: videos, other files and subfolders are skipped without failing. Files deleted from the folder are removed from the bucket on the next sync. Renamed files and edited descriptions update without re-copying.
- Taken date comes from the photo's EXIF time (falls back to the Drive creation time); newest first. Caption = the Drive file description.
- Viewing is open, like the Drawings gallery (`storage.rules` allows read on `photos/`). Writing is only possible with the service account.
- Sync: `cd control-ui && npm ci && GOOGLE_APPLICATION_CREDENTIALS=key.json node scripts/sync-photos.mjs` (add `DRY_RUN=1` to preview), or the GitHub Action **Sync photos** (Actions tab, Run workflow). There is no button on the page: the site has no login, so an admin-only button would have nothing to check.

## Choosing the folder

Set `POND_PHOTOS_FOLDER_ID` (GitHub repo secret or variable, Settings → Secrets and variables → Actions). To get the ID: open the folder in Drive; the URL is `https://drive.google.com/drive/folders/<ID>`; copy the part after `folders/` (drop any `?...`).
Without an ID the script follows the path `Pond 2.0/Images and Videos/Online Gallery/Pond 1.0` (first name = shared drive or top-level folder); override with `POND_PHOTOS_FOLDER_PATH`. Later galleries (e.g. `Pond 2.0` next to `Pond 1.0`) only need another ID or path. Today one folder feeds the page.

## Dani: manual steps (once)

Already done: `github-deployer@pond-grow.iam.gserviceaccount.com` is Viewer on the Pond 2.0 shared drive, the Drive API is enabled, and the storage role is granted.

1. Set the folder ID: copy it from the URL of **Pond 1.0** (see above) and save it as the GitHub secret/variable `POND_PHOTOS_FOLDER_ID`.
2. Allow the site to read the photo list from the browser: `gcloud storage buckets update gs://pond-grow.firebasestorage.app --cors-file=control-ui/photos-cors.json`.
3. Deploy the storage rules: `cd control-ui && firebase deploy --only storage`.
4. Run **Sync photos** (Actions tab → Run workflow), then open `/photos`.
5. If the bucket name in the Firebase console (Storage) is not `pond-grow.firebasestorage.app`, change `BUCKET` in `docs/photos/index.html`, the default in `scripts/sync-photos.mjs`, and step 2.
