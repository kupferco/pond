# Gallery page

`/gallery` (labelled "Gallery"; `/photos` redirects to it) shows images and videos documenting Pond. The old Drawings page now lives at `/drawings`. Source of truth: the Drive folder **Online Gallery** in `Pond 2.0` (shared drive) → `Images and Videos` → `Online Gallery`. Each **subfolder** of it is a **category** on the page (today `Pond 1.0`; add `Pond 2.0` etc. in Drive and it shows up on the next sync, no code change). Never synced: the sibling `Archive` folder or anything else outside Online Gallery.

- Category name = subfolder name as written in Drive; renames and removals follow on the next sync. Folders nested deeper fold into their top-level subfolder's category. Files directly in Online Gallery go into an **Other** category (shown last).
- Category order: alphabetical (numeric-aware), Other last. Inside a category, newest first (taken date).
- Storage (bucket of project `pond-grow`, folder `photos/`, not git): `web/<id>.jpg` (max 1600 px) and `thumb/<id>.jpg` (400 px) for images; `video/<id>.mp4` plus `thumb/<id>.jpg` (poster) for videos; `index.json`.
- **Videos**: mp4, mov/QuickTime, webm (any `video/*`). iPhone .mov (often HEVC) does not play in every browser, so every video is transcoded during sync with `ffmpeg` to H.264/AAC mp4, max 1280 px, `faststart`; the page plays it inline (controls, muted, poster, no autoplay). Videos over 200 MB (`MAX_VIDEO_MB`) are skipped with a log line. Other file types are ignored without failing.
- Idempotent: a file is skipped when its Drive id and modified time are unchanged (no re-upload, no re-transcode). Moves between folders, renames and description edits update without re-copying. Files deleted from Drive (or now over the size limit) are removed from the bucket.
- Taken date comes from EXIF (falls back to the Drive creation time). Caption = Drive file description.
- Viewing is open, like the Drawings page (`storage.rules` allows read on `photos/`). Seeking works: the Storage download endpoint serves HTTP range requests, and `photos-cors.json` exposes the range headers. Writing is only possible with the service account.
- Sync: `cd control-ui && npm ci && GOOGLE_APPLICATION_CREDENTIALS=key.json node scripts/sync-photos.mjs` (needs `ffmpeg` on PATH; `DRY_RUN=1` to preview), or the GitHub Action **Sync photos** (Actions tab, Run workflow; the workflow installs ffmpeg with apt and fails if it is missing). No button on the page: the site has no login, so an admin-only button would have nothing to check.

## Choosing the folder

Set `POND_GALLERY_FOLDER_ID` (GitHub repo secret or variable, Settings → Secrets and variables → Actions) to the ID of **Online Gallery** (not of a category folder). Open the folder in Drive; the URL is `https://drive.google.com/drive/folders/<ID>`; copy the part after `folders/` (drop any `?...`).
Without an ID the script follows `Pond 2.0/Images and Videos/Online Gallery` (first name = shared drive or top-level folder); override with `POND_GALLERY_FOLDER_PATH`. Shared drives work (`supportsAllDrives` / `includeItemsFromAllDrives` on every call), and My Drive folders too.

## Dani: manual steps (once)

Already done: `github-deployer@pond-grow.iam.gserviceaccount.com` is Viewer on the Pond 2.0 shared drive, the Drive API is enabled, and the storage role is granted.

1. Set the folder ID: copy it from the URL of **Online Gallery** (see above) and save it as the GitHub secret/variable `POND_GALLERY_FOLDER_ID`. (The old `POND_PHOTOS_FOLDER_ID` is no longer used.)
2. Update the bucket CORS (now also exposes range headers for video seeking): `gcloud storage buckets update gs://pond-grow.firebasestorage.app --cors-file=control-ui/photos-cors.json`.
3. Deploy the storage rules: `cd control-ui && firebase deploy --only storage`.
4. Run **Sync photos** (Actions tab → Run workflow), then open `/gallery`. The first run with videos takes a few minutes (transcoding).
5. If the bucket name in the Firebase console (Storage) is not `pond-grow.firebasestorage.app`, change `BUCKET` in `docs/gallery/index.html`, the default in `scripts/sync-photos.mjs`, and step 2.
